# 解説 M4-A：モジュール型との比較（End-to-End 対 モジュール型）

実施：2026-10-17　／　計画：[[M4計画案_A_モジュール型との比較]]　／　関連：[[解説_M3]]・[[M4計画案_一覧]]

## 0. ひとことで言うと
**学習を使わず、画像処理で瞳孔を見つけて比例制御で動かす「モジュール型」を作り、M3の生徒（End-to-End）と同じ患者・同じ条件で比べた。** モジュール型は、学習なしで**左眼にも100%合わせられた**（右眼だけで学習した生徒は0%で、右眼へ行ってしまう）。一方、**暗い条件では、瞳孔と虹彩の明るさの差が小さく、瞳孔を見失った**。精度（最終誤差）は、生徒のほうが良かった。

| | End-to-End（M3の生徒） | モジュール型（M4-A） |
|---|---|---|
| しくみ | 画像 → CNN → 指令（全部まとめて学習） | 画像 → ①瞳孔を検出（画像処理）→ ②比例制御 → 指令 |
| 学習 | お手本3.6万組で学習 | なし（校正だけ） |
| 何を見ているか | 分かりにくい（顔の輪郭まで使っていた） | 瞳孔の円だけ（検出した円を表示できる） |

## 1. モジュール型の作り方（`policies/modular.py`）
```
画像 96×96
 ① 灰色にして少しぼかす
 ② しきい値を、いちばん暗い値から少しずつ上げていく
    瞳孔はまず暗い円として現れ → 縁まで取れて中心が安定 → やがて虹彩の影とつながって崩れる
    崩れる直前の結果を使う（同じかたまりを追いかけ、中心が1画素以上動く／面積が1.6倍以上になったら止める）
 ③ 各しきい値で：白い反射点を埋める → 画面の端にかからない・大きさ（半径1.2〜4.5mm）・丸さが合うものを候補に
 ④ 瞳孔の中心 − 画面の中央 を mm に（1mm ≒ 1.85画素、画像の上＝＋z）
 ⑤ 校正：いつも出る一定のずれを差し引く
 ⑥ 指令 ＝ 0.5 × ずれ（最大±3mm）。見つからなければ動かない
```

### 作る途中で分かったこと（検出精度、お手本画像4,000枚で確認：`scripts/m4a_detect_check.py`）
| 版 | 見つからない | 取り違え（3mm以上） | 誤差の中央値 | 95%点 | 最大 |
|---|---|---|---|---|---|
| 1. しきい値1つ（暗いほうから4%） | **14.3%** | 0.8% | 0.07mm | 0.26mm | 39mm |
| 2. しきい値を上げていき、最後に残ったもの | 0% | 0.1% | 0.26mm | 1.41mm | 35mm |
| **3. 同じかたまりを追い、崩れる直前で止める＋画面の端を除く（採用）** | **0%** | **0%** | 0.22mm | 0.70mm | **1.24mm** |

- 版1の失敗：明るい画像では「暗いほうから4%」に**虹彩全体**が入ってしまい、瞳孔より大きいかたまりになって候補から外れた。小さい瞳孔（縮瞳）ほど失敗した。
- 版2の失敗：しきい値を上げすぎると、**虹彩の左下の影**（細隙光が右上から当たるため暗い）が瞳孔とつながり、中心が左下にずれた。画面の隅の暗い背景を瞳孔と取り違えることもあった。
- **校正：** 版3でも、検出した中心はいつも**左下へ約0.1mm（横）・0.2mm（縦）**ずれていた（倍率は正しい：傾き1.005）。原因は版2と同じく照明の向き。実機で設置時に1回行う「校正」に相当するものとして、**右眼のお手本だけ**で測った平均のずれを差し引く（左眼は公平な試験のまま）。

## 3. 分かったこと
1. **モジュール型は、学習なしで左眼にも100%合わせられた（予想どおり）。** 瞳孔の円そのものしか見ないので、「右眼か左眼か」という顔の手がかりに左右されない。M3の生徒が右眼へ行ってしまった近道学習とは対照的。
2. **精度は End-to-End の生徒のほうが良い。** 最終誤差は、BC+DAgger 0.027mm に対し、モジュール型 0.16mm。生徒は特権情報のラベルで学ぶので、照明による見かけのずれまで含めて補正できている。モジュール型は、校正しても照明や虹彩の色でずれ方が変わる（灰色の虹彩では校正なしのほうが良かった：0.08 対 0.16mm）。
3. **暗い条件では、モジュール型も弱い（86%）。** 失敗した7人は、最初から瞳孔を1度も見つけられず、その場で止まっていた（「見つからなければ動かない」の設計どおり、暴走はしない）。原因は、暗いと**瞳孔と虹彩の明るさの差が数段階しかなく**、瞳孔が円になる前に虹彩とつながること。顔の影が瞳孔より暗くなることもあった。検出は明るい学習用の画像だけで作ったので、暗い条件に合わせた調整はしていない（試験の条件に合わせて調整すると、公平な比較にならない）。
4. **失敗の仕方が違う。**
   - End-to-End：左眼で、**自信を持って間違った場所（右眼）へ64mm移動**した。外から見て、なぜそうしたかが分からない。
   - モジュール型：暗いと「見つからない」と分かり、**動かない**。検出した円を表示できるので、なぜ動かないかも分かる。
   - 医療機器としては、後者のほうが安全で、説明しやすい。
5. **両眼で学習した生徒（③）は、暗い条件で74%に下がった**（右眼だけのBCは84%）。データが両眼に分かれ、1つの眼あたりの学習量が同じでも、条件の変化への強さは上がらなかった。50人での差なので、確かめるなら人数を増やす必要がある。

## 4. レポートでの位置づけ
- 講義の End-to-End 対モジュール型の論点（講義資料 p.29）を、同じシミュレータ・同じ患者での実験で示した。
- **End-to-End：** 精度が高く、特権情報のラベルで照明のくせまで補正できる。ただし、何を手がかりにしているかが見えず、学習の範囲外（左眼）では自信を持って誤る。
- **モジュール型：** 作り込み（しきい値の追い方、校正）が要り、精度は劣る。ただし、何を見ているかが明確で、範囲外の条件（左眼）にもそのまま使える。失敗するときは「見つからない」と分かる。
- **組み合わせの可能性：** モジュール型で「瞳孔はここ」と確かめつつ、生徒の指令で細かく合わせる（生徒の指令が検出した瞳孔と大きく食い違えば止める＝安全装置）。

1. `policies/modular.py` の `detect_pupil` で、`max_shift_px` を 1.0 → 3.0 にして `m4a_detect_check.py` を実行する。虹彩の影とつながるのを許すと、誤差がどう変わるか。
2. dark で失敗した患者（seed 10010 など）の画像を開き、瞳孔と虹彩の明るさの差を自分の目で確かめる。どう検出すれば見つけられそうか。
