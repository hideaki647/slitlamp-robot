# 解説 M4-E：瞬き（瞳孔が一時的に隠れても暴れない）

実施：2026-10-20〜21　／　計画：[[M4計画案_E_瞬き]]　／　関連：[[解説_M4A]]・[[解説_M4G]]・[[M4計画案_一覧]]

## 0. ひとことで言うと
右眼に**上瞼・下瞼**を作り、患者が瞬きをするようにした。瞬きを知らない生徒は、瞼が閉じている間に**平均0.5mm、最大1.8mm**動いてしまった。**瞬きのお手本で学んだ生徒は、瞬き中の動きが平均0.05〜0.08mm**に収まり、直前の画像も見るフレームスタックの生徒が最も安定した（最大0.13mm）。もう一つの発見として、**瞼の見た目そのもの**（瞬きしなくても）が、学習時に瞼が無かった生徒の精度を下げた。

## 1. 瞼を作る（`scripts/make_lids.py` → `models/lids/*.obj`、`models/scene.xml`）
### 1.1 最終的な作り方
- 瞼は、眼球（半径12mm）を包む**半径14.6mm の球面の一部（殻）**。
- 正面から見た瞼の縁の形を、曲線で決める。
  - **上瞼の縁：中央が高いアーチ** z = h(c)·(1 − (x/W)²)。両端は内眼角・外眼角（x = ±13mm）で z=0。
  - **下瞼の縁：中央が低いアーチ** z = −5.5mm·(1 − (x/W)²) ＋ 0.3mm（目頭・目尻で上瞼と少し重なり、瞼裂が閉じる）。
  - その結果、上下の瞼の間（**瞼裂**）は**アーモンド形**になる（幅約26mm）。
- 上瞼は、閉じ具合 c = 0〜1 ごとに**13個の形**を前もって作り、シミュレータが c にいちばん近い形だけを表示する（使わない形は眼球の奥に隠す）。
  - c=0（普段）：縁の中央が瞳孔中心の **4.5mm 上**（虹彩の上端に1.5mm かかる）。
  - c=1（閉じる）：縁の中央が下瞼の縁より0.8mm 下まで降り、眼を完全に覆う。
- 下瞼は動かない。
- 瞬き機能を使わない設定（既定）では、瞼をすべて隠す（M2〜M4の結果はそのまま有効）。
- 確認用の画像：`outputs/m4e_lid_check.png`

### 1.2 試作の経過（つまずき）
| 試作 | 問題 |
|---|---|
| 1. 眼の上に肌色の球（半径15mm）を置き、下へ動かす | 眼の上に**ボールが乗っている**ように見えた。開いた状態で虹彩の1/3を覆った |
| 2. 球を上だけでなく奥へも動かす | 途中まで眼が全部見え、最後に**急に消える**。瞼らしくない |
| 3. 眼球を包む半球の殻を、眼の中心のまわりに前へ回す | 三角形の向き（表裏）で**面が消える**→ 表と裏の両方の向きの三角形を入れて解決。半径13.3mm では閉じても**虹彩が透けた**（虹彩の前面12.6mm との差0.7mm で描画の前後関係が崩れた）→ 14.6mm で解決。ただし縁の形が回転で決まり、**アーチにならない** |
| **4. 縁の形を曲線で決め、閉じ具合ごとに形を作る（採用）** | ユーザー（眼科医）の指摘で、**上瞼の縁を中央が高いアーチ**にし、**下瞼**を追加した |

- **簡略化（レポートに明記）：** 睫毛なし、ベル現象（閉じたときに眼球が上へ回る）なし、瞼の厚み・縁の色なし。

## 2. 瞬きの時間（`sim/env.py` の `blink`）
| 設定 | 内容 |
|---|---|
| `None`（既定） | 瞼なし（これまでと同じ） |
| `"rest"` | 瞼はあるが瞬きしない |
| `"random"`（学習用） | 最初は0.3〜1.5秒後、その後1.5〜4秒おきに瞬き |
| `"eval"`（評価用） | **1.0秒と2.5秒**に必ず瞬き |

- 1回の瞬き：閉じる0.1秒 → 閉じたまま0〜0.15秒（評価は0.1秒）→ 開く0.15秒。細隙光でまぶしい想定で、普段より多め。
- 瞼は物理計算の細かい刻み（0.02秒）で動かすので、**半分閉じた画像**も生じる。
- **瞳孔が隠れている**＝閉じ具合 0.42 以上（上瞼の縁の中央が瞳孔中心より下）。

## 3. 先生のふるまいと、比べた方式
- **先生：瞳孔が隠れている間は指令0（待つ）**。先生は本当の位置を知っているので動けてしまうが、生徒は画像から同じことができないので、生徒が真似できるふるまいにそろえた。臨床でも瞬きの間は待つ。
- **フレームスタック**（`learning/model.py` の `stack`）：今の画像と、0.1秒前・0.2秒前の画像を重ねて入力する（色3チャンネル×3枚）。「さっきまで合っていた」が分かる。

| 方式 | 学習 |
|---|---|
| 先生（待つ） | — |
| モジュール型（M4-A） | なし（瞳孔が見つからなければ動かない） |
| BC・BC+DAgger（M3） | 瞬きも瞼も知らない |
| **瞬きを学んだ生徒（1枚）** | 瞬きありのお手本 9万組（3,000人×3秒、`data/demos_blink`）で25周 |
| **瞬きを学んだ生徒（フレームスタック3枚）** | 同じお手本で25周 |

## 4. 結果（未知の患者50人、5秒間、途中で打ち切らない）
### 瞬きあり（1.0秒・2.5秒）
| 方式 | 瞬き中の動き（平均／最大） | 最後に合っていた割合 | 合っていた時間の割合 |
|---|---|---|---|
| 先生（待つ） | 0.00 / 0.00 mm | 100% | 100% |
| モジュール型 | 0.06 / 0.30 mm | 100% | 100% |
| BC（瞬きを知らない） | **0.57 / 1.80 mm** | **92%** | 89% |
| BC+DAgger（瞬きを知らない） | **0.54 / 0.87 mm** | 100% | 96% |
| 瞬きを学んだ生徒（1枚） | 0.08 / 0.29 mm | 100% | 100% |
| **瞬きを学んだ生徒（3枚）** | **0.05 / 0.13 mm** | 100% | 100% |

- 瞬き中の動き＝瞬きの直前の本体の位置から、瞬きが終わるまでにどれだけ動いたか（患者ごとの最大値の、平均と最大）。
- 合わせ直しの時間は、どの方式もほぼ0秒（瞬き中に1mm以上離れなかったため）。

## 5. 分かったこと
1. **瞬きを知らない生徒は、瞬きの間に動いてしまう**（平均0.5mm、最大1.8mm）。瞳孔が見えない画像は学習の範囲外で、何らかの指令を出してしまう。患者の顔の近くで動くロボットとして、**安全上の課題**。
2. **瞬きのお手本で学ぶと、「待つ」を学べる**（平均0.05〜0.08mm）。先生が「瞳孔が隠れたら待つ」をお手本で示したので、生徒は閉じた瞼の画像から「動かない」を真似できた。
3. **フレームスタックは、最悪の場合を小さくした**（最大0.29 → 0.13mm）。半分閉じた途中の画像で、1枚だけでは迷う場面があり、直前の画像（まだ瞳孔が見えていた）が手がかりになったと考えられる。平均ではほぼ同じ。
4. **モジュール型は「見つからなければ動かない」設計なので、もともと強い**（平均0.06mm）。半分閉じた瞳孔の中心を取り違えて動く場面が少しあった（最大0.30mm）。
5. **見た目の違いへの弱さ（予想外の発見）：** 瞼を知らない生徒は、**瞬きしなくても瞼があるだけで精度が落ちた**（BC 0.058 → 0.48mm）。逆に、瞼ありで学んだ生徒は、**瞼が無いと精度が落ちた**（0.058 → 0.44mm、成功率96%）。End-to-End の生徒は、瞳孔だけでなく**眼のまわりの見た目全体**を手がかりにしている（M3 §12 の近道学習と同じ性質）。実機では、瞼の形・睫毛・化粧など、見た目のばらつきを学習データに含める必要がある。

## 6. レポートでの位置づけ
- **安全性：** 「分からないときは動かない」を、モジュール型は設計で、生徒はお手本で実現できる。お手本（先生のふるまい）の設計が、そのまま生徒の安全性になる。
- **記憶の役割：** フレームスタックは、半分閉じた途中のような「1枚では決まらない」場面で効く。M4-G（遅れ）の案2とも共通する。
- **臨床のリアルさ：** まぶしさによる瞬き、上瞼の縁のアーチ、アーモンド形の瞼裂など、眼科医の知識をシミュレータに反映した（瞼の形は、ユーザーの指摘で修正）。

## 7. 記録（つまずき）
- 瞼の試作4回（§1.2）。
- フレームスタックを加えるとき、`learning/train_bc.py` で新しい関数 `stacked` を `@torch.no_grad()` と `evaluate` の間に入れてしまい、`evaluate` で勾配が切れずに1周目の終わりで止まった。デコレーターを `evaluate` に付け直した。
- メモリ（16GB）に収めるため、瞬きを学ぶ生徒は、瞬きありのお手本（9万組）だけで学習した（右眼のお手本3.6万組は混ぜなかった）。2つの学習を並列に実行し、約1.5〜2時間かかった。
