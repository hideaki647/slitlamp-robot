# 解説 M3：生徒AIの模倣学習（BC → DAgger）と評価

## 0. ひとことで言うと：M3で何をしたのか
**細隙灯カメラの画像だけを見て、細隙灯を瞳孔に合わせる「生徒AI」を作った。** M2の先生は「瞳孔の本当の位置」というカンニングペーパーを持っていたが、生徒は画像しか見ない。それでも先生とほぼ同じ速さ・正確さで合わせられるようになった。**ここが課題の合格ライン。**

### やったことは4つ
1. **生徒の脳（CNN）を作った：** 96×96の画像を入れると、指令（Δx, Δz mm）が出てくる小さなニューラルネット。
2. **BC（行動クローニング）：** M2のお手本3.6万組で「この見え方なら、先生はこう動かした」を学ばせた（筆記試験の勉強）。
3. **DAgger：** 生徒が自分で操作し、通った場面すべてに先生が正解を書き込み、教材に足して学び直す。これを4回くり返した。
4. **実技試験：** 一度も見たことのない患者50人で、一人で操作させた。さらに、学習時に無かった条件（暗い・明るい・灰色の虹彩・頭が大きくずれる）でも試した。

### 研修医にたとえると
| プロジェクト | たとえ |
|---|---|
| BC | 指導医の操作の録画（症例写真集）を見て、「この見え方ならこう動かす」を覚える |
| 筆記試験（確認用データ） | 勉強に使っていない写真で、指導医と同じ判断ができるかを確かめる |
| 実技試験（評価） | 初めての患者で、一人で細隙灯を合わせる |
| 分布シフト | 一人で操作すると少しずつずれ、録画で見たことのない見え方に入り込んで戸惑う |
| DAgger | 研修医が操作し、横で指導医が「今の見え方ならこう動かす」と正解を書き込む。それを教材に足して学び直す |
| 汎化テスト | 照明が暗い診察室、見慣れない虹彩の色の患者などで試す |

## 1. 全体の流れ
```
M2のお手本 3.6万組（画像＋先生の指令）
   │ ① BC：40周くり返し学習（約18分）
   ▼
生徒 BC ── 実技試験（未知の患者50人 × 5条件）
   │ ② DAgger 1ラウンド：
   │    生徒が500回操作（各3秒）→ 通った場面すべてに先生が正解を付ける（＋1.5万組）
   │    → 全データで続きから学習（15周）→ 実技試験
   │    これを4ラウンド（合計 9.6万組、約59分）
   ▼
生徒 BC+DAgger ── 実技試験（未知の患者50人 × 5条件）
```

## 2. 用語
| 用語 | 意味 |
|---|---|
| **CNN（畳み込みニューラルネットワーク）** | 画像から特徴（縁・模様など）を拾い出すのが得意なニューラルネット。 |
| **空間ソフトマックス** | CNNが見つけた特徴が「画像のどこにあるか」を座標で取り出す層（Levine et al., 2016）。画素より細かい位置が出せる。ロボット学習でよく使う。 |
| **BC（Behavior Cloning、行動クローニング）** | お手本の「入力 → 行動」の組を、教師あり学習でそのまま真似る方法。 |
| **エポック（周）** | 勉強用データを1周すること。 |
| **学習用／確認用データ** | 学習用で勉強し、確認用（勉強に使わない）で成績を測る。患者単位で分けて、似た画像がテストに混ざらないようにする。 |
| **過学習** | 勉強用データを丸暗記してしまい、新しい問題に弱くなること。 |
| **データ拡張** | 学習のたびに、画像の明るさ・色味・コントラストを少し変えて見せること。照明の違いに強くなる。 |
| **分布シフト** | 生徒が自分で操作すると、お手本には無かった状態に入り込み、誤りが積み重なること。 |
| **DAgger（Dataset Aggregation）** | 生徒が実際に行った状態に先生の正解を付けてデータに加え、学び直す方法（Ross et al., 2011）。分布シフトへの代表的な対策。 |
| **汎化** | 学習時に無かった条件でもうまく動けること。 |
| **OOD（Out-of-Distribution）** | 学習データの範囲の外の条件。 |

## 3. 生徒の脳（learning/model.py）
```
画像 96×96×3
 → 畳み込み 5×5（ずらし幅2）→ 48×48×32
 → 畳み込み 3×3 → 畳み込み 3×3 → 1×1 で16枚の「特徴マップ」
 → 空間ソフトマックス：16個の特徴点の (x, y) 座標 ＝ 32個の数
 → 全結合 128 → 128 → 2 ＝ 指令 (Δx, Δz)
```
- **なぜ空間ソフトマックスか：** 細隙灯カメラでは 1mm ≒ 1.85画素で、合格範囲（1mm）は約2画素しかない。瞳孔の位置を画素以下の細かさで読む必要がある。
- パラメータは約3万個。小さいのでCPUだけで学習できる（1周26秒）。
- 生徒は `env`（シミュレータの内部情報）を一切使わず、画像だけで指令を決める。

## 4. BC：筆記試験の勉強（learning/train_bc.py）
- データ：3.6万組を、勉強用 3.24万組と確認用 3,600組に分ける（患者の番号が10の倍数の300人分を確認用に）。
- 1周の中では、256組ずつ「見る → 先生とのずれを計算 → 脳の数値を少し直す」を約126回くり返す。毎周、出題順をシャッフルする。
- データ拡張：明るさ ×0.75〜1.25、色味 ×0.9〜1.1、コントラスト ×0.8〜1.2、ノイズ。
- 学習率：はじめは大きく直して早く上達させ、終盤は細かく直して仕上げる（OneCycle）。

### 学習の経過（確認用データでの、生徒の指令と先生の指令のずれ）
| 周 | 全体 | 微調整の場面（ずれ<2mm） | 大きく動かす場面 |
|---|---|---|---|
| 1 | 1.12mm | 0.48mm | 2.50mm |
| 5 | 0.28mm | 0.19mm | 0.49mm |
| 10 | 0.14mm | 0.11mm | 0.21mm |
| 20 | 0.067mm | 0.051mm | 0.100mm |
| **40** | **0.049mm** | **0.038mm** | **0.074mm** |

- 指令は最大3mmなので、0.05mmのずれは先生とほぼ同じ判断ができているということ。
- 勉強用と確認用の成績が一緒に下がっているので、丸暗記（過学習）は起きていない。

## 5. 実技試験の方法（scripts/eval_policy.py）
- **一度も見たことのない患者50人**（seed 10000〜10049）に、1回ずつ操作させる。お手本（seed 0〜2999）やDAggerの練習（seed 21000〜）とは重ならない。
- 細隙灯は、瞳孔から平均9.6mmずれた位置から始める。
- **合格：** ずれ1mm未満を5回（0.5秒）続けて保てたとき。5秒以内に合格できなければ不合格。
- 先生・BC・BC+DAgger が**同じ50人**を受けるので、差は純粋に方式の差になる。
- 50人だと成功率は2%刻みで、2〜3人の差は偶然でも起こりうる。差が出た条件は200人で測り直す。

### 汎化テストの条件（sim/env.py の `CONDITIONS`）
| 条件 | 内容 | 学習時の範囲 |
|---|---|---|
| normal | 学習時と同じ | — |
| dark | 細隙光・室内光 ×0.45〜0.55 | ×0.7〜1.3 |
| bright | 細隙光・室内光 ×1.5〜1.6 | ×0.7〜1.3 |
| gray_iris | 灰色の虹彩 | 茶・ヘーゼル・緑・青の5色 |
| head_far | 頭の位置 左右±10〜14mm、上下±8〜11mm | 左右±10mm、上下±8mm |

- 生徒が見ている画像の例：`outputs/m3_conditions.png`（上から normal・dark・bright・gray_iris）。dark では白目まで灰色になり、白目と虹彩の境目がぼやける。

## 6. 結果
### BC の実技試験
- normal で**成功率100%、収束0.44秒**。先生（0.43秒）と同じ速さ。
- 最終誤差は 0.072mm で、先生（0.024mm）より少し大きい。
- 汎化テストでは **dark だけ成功率84%**（50人中8人が不合格）。ほかの条件は100%。

### DAggerとは（詳しく）
**Dataset Aggregation（データの継ぎ足し）** の略で、2011年に提案された模倣学習の方法（Ross et al.）。**生徒に自分で操作させ、生徒が実際に行った場面に先生が正解を書き込んで、教材に足していく。**

#### なぜ必要か：BCの弱点（分布シフト）
BCでは、生徒は「先生が操作したときに出会った場面」だけで勉強する。生徒が一人で操作すると、次のことが起こる。
1. 生徒の指令が、先生より少しだけずれる（例：0.05mm）。
2. 細隙灯が、先生なら行かない位置に少しずれる。
3. その位置の見え方は、教材にほとんど無い。
4. 戸惑ってさらにずれ、ずれが積み重なる。

研修医が写真集で勉強したのに、自分で操作すると写真集に無い見え方に入り込んでしまう状態。

#### やり方（1ラウンド）
```
① 生徒が自分で操作する（500回）
② 生徒が通った場面すべてに、先生が「この見え方ならこう動かす」と正解を書き込む
   （先生は瞳孔の本当の位置を知っているので、どんな場面でも正解を出せる）
③ その組を教材に足す（3.6万組 → 5.1万組 → …）
④ 増えた教材で学び直す
```
これを4回くり返すと、生徒が実際に迷い込みやすい場面ほど、教材に正解付きで入っていく。

| | BC | DAgger |
|---|---|---|
| 勉強の仕方 | 指導医の操作の録画を見て覚える | 自分で操作し、横で指導医が「今のはこう」と正解を書き込んでいく |
| 教材の場面 | 指導医がうまく操作したときの場面だけ | 自分がずれた場面も含む |
| 弱点 | 自分のずれから戻る方法を知らない | 指導医がずっと横にいる必要がある |

#### 今回の状況と限界
- 通常の条件では、BCの時点ですでに成功率100%で、分布シフトはあまり起きていない。先生の操作が単純でぶれないこと、お手本を集めるときにわざと少しずらしていたこと（DART）が効いている。
- そのため、DAggerの効果は**成功率よりも、合った後の精度（最終誤差）**に出ている。
- **限界：** 正解を書き込める先生がいることが前提。シミュレータでは自動でできるが、実機では人間が毎回正解を付ける必要があり、手間がかかる。この点はレポートの考察で扱う。

## 7. 考察（レポートに使う論点）
1. **画像だけで、先生とほぼ同じ速さで合わせられた。** 特権情報を持つ先生 → 画像だけの生徒、という教え方が機能した。
2. **DAggerの効果は「精度」と「頑健さ」に出た。** 通常の条件では成功率に差がなく、最終誤差が約4割減った。暗い条件では成功率が 86% → 98% に上がった。
3. **注意（公平な比較のための残り課題）：** DAggerの生徒は、BCより多くのデータ（9.6万組 vs 3.6万組）と多くの学習（40周＋60周）を受けている。そのため、暗い条件での改善が「生徒自身が行く場面を学んだ効果（DAggerの本質）」なのか、「データと学習量が増えた効果」なのかは、まだ切り分けられていない。切り分けるには「先生のお手本を9.6万組に増やしたBC」と比べる必要がある。
4. **暗い条件が弱点。** 学習時の明るさの範囲（×0.7〜1.3）を広げる（ドメインランダム化の拡大）と、さらに改善する見込み。
5. **Sim-to-Real：** 実機では、実際の眼の画像（睫毛・角膜反射・瞬き・眼球運動）との見え方の違いが課題になる。

## 12. 追加実験：左眼にも対応させる（10/17）
### 問い
右眼だけで学習した生徒は、左眼にも合わせられるか。だめなら「左右反転」でよいのか、「左眼でも同じ学習」が必要か。

### 前提：制御側は変えなくてよい
- 生徒の指令は「本体を右へΔx、上へΔz」という差分で、左眼でも本体の向きは同じ。アーム・IK・ジョイスティックはそのまま使える。
- 先生も、目印を `pupil_L_center` に替えるだけで左眼に合わせられる（`SlitLampEnv(target_eye="L")`）。
- 違うのは**生徒が見る画像**だけ：瞳孔・虹彩は同じ円形だが、顔の輪郭（鼻側・耳側）が左右逆に写り、細隙光の当たり方も変わる（光源は片側に固定）。
- 比較画像：`outputs/m3_eyeR_vs_L.png`（上が右眼、下が左眼）。

### 3つのやり方
| | やり方 | 新しいデータ | 学習 |
|---|---|---|---|
| ① | 何もしない（右眼で学習した生徒をそのまま左眼で試す） | なし | なし |
| ② | **左右反転のデータ拡張**：右眼の画像の半分を左右反転し、正解の Δx の符号を逆にして学ぶ（`train_bc.py --flip`） | なし | 40周（約30分） |
| ③ | **左眼のお手本も集める**：先生に左眼でも3,000人分を操作させ（3.6万組、約7分）、両眼の7.2万組で学ぶ | 3.6万組 | 40周（約46分） |

### ① の結果：生徒は左眼を無視して、右眼まで移動した
- BC・BC+DAgger とも、左眼では**50人全員が不合格**。最終誤差は約64mm＝両眼の間の距離。
- 1人目の患者で動きを追った結果：

| 時刻 | 左眼とのずれ | 右眼とのずれ | 生徒の指令 Δx |
|---|---|---|---|
| 0.0秒 | **+6.2mm**（すぐ近く） | −57.8mm | **−1.9**（左眼と反対向き） |
| 1.2秒 | +29.8mm | −34.2mm | −0.8 |
| 2.4秒 | +56.8mm | −7.2mm | −3.0 |
| 3.2秒 | +64.0mm | **0.0mm**（右眼に合った） | 0 |

- **なぜ：** 生徒が学んだのは「写った瞳孔を中央に合わせる」ではなく、「**患者の右眼へ行く**」だった。学習中の正解はいつも右眼だったので、生徒は瞳孔だけでなく、顔の輪郭や頬の陰影も手がかりに「右眼はどこか」を推定していた。左眼の画像を見ても「この顔なら右眼はあちら」と読み、正しく右眼へ向かった（左眼は学習中、一度も画面に写っていない）。
- これは**近道学習（ショートカット学習）**と呼ばれる現象。画像から直接操作を学ぶ方式（End-to-End）は、人間が意図したのとは違う手がかりを使い、学習した課題だけは正確にこなすことがある。

### 途中で見つけたアームの不具合と修正
- 先生も左眼で50人中1人だけ不合格だった（高さが2.58mm足りない）。
- **原因：** 手首の回転関節が可動範囲の端（−270°）に当たっていた。手首の回転は「ハンドル角の逆向き＋一定のずれ」で決まるが、向きだけを見るIKには360°ずれた解も同じに見える。握るときに「1回転ずれた解」を選ぶと、ハンドルを100°ほど回しただけで手首が限界に当たる。
- **修正：**
  1. 握るとき、ハンドル0°の姿勢から連続につながる手首の角度を選ぶ（`sim/slitlamp_api.py` の `grasp`）。
  2. 手首の可動範囲を ±270° → ±360° に広げた（`models/scene.xml`。実際の産業用ロボットの手首は±360°以上が多い）。
  3. IKの出発点が既に正解のとき、可動範囲の確認を飛ばしていた小さなバグを直した（`sim/arm_ik.py`）。
- **結果：** 先生は両眼で成功率100%、最終誤差 0.024 → **0.008mm** に改善。左眼のお手本の到達率も99.8%（右眼の旧データは98.2%。この不具合の影響だったと考えられる）。
- 修正でアームの動きが少し変わったので、すべての生徒を修正後のアームで測り直した（下の表）。

### 結果（未知の患者50人、修正後のアーム）
| 生徒 | 学んだデータ | 右眼 | 左眼 |
|---|---|---|---|
| 先生（参考） | — | 100% / 0.008mm | 100% / 0.008mm |
| BC | 右眼 3.6万組 | 100% / 0.058mm | **0%** / 64mm（右眼へ移動） |
| BC+DAgger | 右眼 9.6万組 | 100% / 0.027mm | **0%** / 57mm（右眼へ移動） |

| ③ 両眼のお手本 | 右眼＋左眼 7.2万組 | **100%** / 0.085mm | **100%** / 0.062mm |

（成功率 / 最終誤差。収束時間はどれも合格した回で約0.43〜0.52秒）

### 分かったこと
1. **「X軸を反転するだけ」では不十分だった（左眼48%）。** 左右対称の世界なら、反転した画像と符号を逆にしたΔxはそのまま正しい組になる。しかしこのシミュレータでは光源が片側に固定なので、左眼では細隙光が虹彩に正面から当たって明るく写る（`outputs/m3_demo_samples_L.png`）。反転画像は光の向きが本物の左眼と逆になり、生徒にとっては「見たことのない左眼」のままだった。右眼の精度も少し落ちた（0.058 → 0.19mm）。
2. **左眼のお手本も集めて学ぶ（③）と、両眼とも100%になった。** 先生（特権情報）がいれば新しい課題のお手本は自動で作れるので、シミュレータでは「同じ学習をもう一度」が最も確実で、コストも小さい（収集7分＋学習46分）。
3. **眼科の実際との対応：** 実際の診察では、スリット光を眼ごとに振り直す（たとえば耳側から当てる）。シミュレータでも光源を眼ごとに鏡像の位置へ動かせば、左眼の場面はほぼ右眼の鏡像になり、②の反転がそのまま成り立つはず。
4. **残る課題（M4候補「両眼切替」）：** 両眼の間は64mmで、細隙灯カメラの視野（横約52mm）より広い。右眼に合わせた状態から左眼は画面に写らないので、画像だけの生徒には「どちらの眼へ行くか」が分からない。「左眼へ」という指示を生徒に入力するか、大まかな移動を別の仕組みで行う必要がある。今回の実験は、左眼の近く（±15mm）から開始する場合。

### Layers（層）＝箱を作った手順の記録
イメージは手順ごとの「積み木」になっている。右の数字は、その手順で増えた容量。

| 番号 | 内容 | 容量 | 意味 |
|---|---|---|---|
| 0〜9 | debian・Python 3.12.15 | 約150MB | 土台。公式の `python:3.12-slim-bookworm` に入っている部分 |
| 10 | ENV …MUJOCO_GL… | 0B | 環境変数の設定（画面なしで3D描画する方式 EGL など） |
| 11 | apt-get install libegl1 … ffmpeg | 476MB | 3D描画用のライブラリと、動画を作る ffmpeg |
| **12** | pip install torch==2.11.0 … cpu | **1.01GB** | **PyTorch（生徒AIの学習に使用）**。いちばん大きい |
| 13 | COPY requirements.txt | 12KB | ライブラリ一覧の表をコピー |
| 14 | pip install -r requirements.txt | 529MB | MuJoCo・numpy・OpenCV・matplotlib など |
| 15 | WORKDIR /workspace | 8KB | 作業場所（Windowsの `slitlamp_robot` フォルダとつながる場所） |
| 16 | CMD ["bash"] | 0B | 箱を開けたときに最初に起動するもの |

- **作り直す順番：** 変わった手順より下の層だけが作り直される。例：`requirements.txt` を変えると、0〜12層は使い回され、13〜14層だけが作り直される。1GBの PyTorch を毎回入れ直さずに済むよう、PyTorch の層を先に置いている。
