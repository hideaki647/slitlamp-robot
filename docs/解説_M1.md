# 解説 M1：連動拘束・ロボットアーム・逆運動学（IK）・把持（weld）

## 0. ひとことで言うと：M1で何をしたのか
**ロボットアームがジョイスティックを握り、指令どおりに細隙灯を動かせるようにした。** 「どこへ動かすか」を決める頭脳はまだない。「言われた場所へ正確に動かす手足」を作った段階。

### やったことは3つ
1. **ジョイスティックと細隙灯本体をつないだ（連動拘束）**
   - 実機では、ジョイスティックを倒すと内部の機構で本体が動き、回すとネジで鏡筒が上下する。
   - シミュレータでは「本体の左右位置 = 0.15 × 傾き角」「鏡筒の高さ = 0.00318 × 回転角」というルールを課して再現した（10°倒すと26mm、半回転で10mm）。
2. **6関節のロボットアームを置き、ノブを握らせた**
   - アームは検者の席側に置いた（医師の代わりに操作するイメージ）。
   - 関節が6つあるのは、手先の位置（3つ）と向き（3つ）を合わせるため。人の肩・肘・手首と同じ考え方。
   - 指で摩擦を使って握る計算は不安定なので、手とノブを**溶接（weld）**して一体にした。「握った状態から開始」という簡略化で、レポートに明記する。
3. **「本体をここへ」という指令を、アームの関節角に翻訳する仕組みを作った（逆運動学 IK）**
   - 本体の目標位置 → ジョイスティックの角度 → ノブの位置と向き → アーム6関節の角度、という順に計算する。
   - 最後の段階は式で一発では解けないので、少しずつ近づける繰り返し計算で解く（誤差 0.001mm）。

### 指令から動きまでの流れ
```
「本体を右へ5mm」 → ジョイスティックを何度倒すか → ノブをどこへ持っていくか
   → アームの各関節を何度にするか（IK）→ モーターが関節を動かす
   → 握ったジョイスティックが倒れる → 連動して本体が右へ5mm
```
M2・M3では、この入口の「右へ5mm」を、先生（M2）や生徒AI（M3）が0.1秒ごとに出す。

### 眼科にたとえると
| プロジェクト | たとえ |
|---|---|
| 連動拘束 | ジョイスティック内部のリンク機構・高さ調整ネジ |
| ロボットアーム | 検者の腕 |
| 逆運動学（IK） | 「ここへ動かしたい」と思ったとき、肩・肘・手首を無意識にどう曲げるか |
| weld | ジョイスティックをしっかり握った手 |

### 成果
- 傾き角と本体の移動量の比が、設計どおり（0.1500 と 0.00318）になった。
- アームが握ったまま本体を左右・上下に動かす動画ができた（`outputs/m1_demo.mp4`、真上からの `m1_demo_top.mp4`）。
- 指令への追従誤差は、M1の時点で平均0.82mmだった。M2でモーターの設定（kp/kv 150/15 → 250/6）を見直し、**平均0.19mm、最大0.47mm** に改善した（下の §3・§7 の数値は M1 当時のもの）。

## 1. 全体の流れ
```
指令「本体を x, z へ」                       ← M3 で学習ポリシー（生徒）が出す値
  ↓ ① 換算（sim/slitlamp_api.py: lamp_to_joystick）
ジョイスティック角（左右傾き roll, 回転 spin）
  ↓ ② ノブの目標姿勢（knob_pose）＋ 逆運動学（sim/arm_ik.py）
アーム6関節の目標角 → 位置制御モーター
  ↓ ③ 物理シミュレーション（weld で手とノブが一体）
ジョイスティックが傾く・回る
  ↓ ④ 連動拘束（scene.xml の <equality>）
細隙灯本体が左右・上下に動く
```

## 2. 連動拘束（equality joint, polycoef）
- 「関節A = 係数 × 関節B」というルールを MuJoCo に課す。実機ではリンク機構やネジがこの役をする。
- 本プロジェクトの係数：
  - 本体左右 lamp_x = **0.15** × 左右傾き js_roll（10°倒すと 26mm）
  - 本体前後 lamp_y = **−0.15** × 前後傾き js_pitch（奥へ押すと奥へ）
  - 鏡筒高さ lamp_z = **0.00318** × ハンドル回転 js_spin（半回転で 10mm）
- 符号は「右ねじの法則」で決まる。y軸まわりに + 回すとノブは +x（右）へ倒れる。
- **簡略化**：実機は大きな移動を台ごと滑らせて行い、傾きは微調整に使う。本プロジェクトでは「傾き角＝位置」に一本化した。

## 3. ロボットアーム（6自由度）
| 関節 | 軸 | 役割 |
|---|---|---|
| a_yaw | z | 土台の旋回 |
| a_shoulder | x | 肩 |
| a_elbow | x | 肘 |
| a_wrist_pitch | x | 手首の曲げ |
| a_wrist_dev | y | 手首の横曲げ |
| a_wrist_roll | z | 手首の回転（＝ハンドルを回す） |

- **なぜ6つ必要か**：手先の「位置3つ＋向き3つ」＝6つの量を合わせるには、最低6つの関節がいる。最初の案（5関節）では横曲げがないため、ジョイスティックを左右に倒したときにノブの傾きについていけない。
- 手首の3軸は1点で交わる（球面手首）。人の手首と同じ構造で、位置と向きを分けて考えやすい。
- `gravcomp="1"`：アームの自重を打ち消す（実機の重力補償制御に相当）。モーターは操作に必要な力だけを出せばよい。
- 位置制御モーター：`kp`（ばねの強さ）＝150、`kv`（ダンパー）＝15。「この角度に行け」と指示する。

## 4. 逆運動学（IK）
- **順運動学（FK）**：関節角 → 手先の位置・向き。計算は簡単。
- **逆運動学（IK）**：手先の目標位置・向き → 関節角。一般に式では解けないので、少しずつ近づける。
- **ヤコビアン J**：「各関節を少し動かすと、手先が（位置3＋向き3の）各方向にどれだけ動くか」をまとめた 6×6 の表。
- **減衰付き最小二乗法**：Δq = Jᵀ (J Jᵀ + λ² I)⁻¹ e
  - e：目標とのずれ（位置3つ＋向き3つ）
  - λ（減衰）：腕が伸び切る姿勢など、J がほとんど逆算できない「特異姿勢」で Δq が巨大になって暴れるのを防ぐ。
- 毎回、前回の答えから計算を始める（ウォームスタート）ので、30回程度の繰り返しで収束する。
- **ノブの目標位置は本体の移動も含めて計算する**：ジョイスティックは基台に付いているので、倒すと基台ごと動く。計算専用のデータ（`calc`）にジョイスティック角と本体位置を書き込み、順運動学でノブの位置を求めている。

## 5. 把持（weld 拘束）
- 指と摩擦で掴むのは計算が不安定なため、手とジョイスティックを **weld（溶接）** で一体化する。
- 手順：IK で手をノブの位置に置く → そのときの「手から見たジョイスティックの相対姿勢」を記録 → weld を ON。
- **簡略化**：把持の動作（近づく・指を閉じる）は省略し、「握った状態」から開始する。レポートに明記する。

## 6. M1でのつまずき（記録）
| 症状 | 原因 | 対策 |
|---|---|---|
| 鏡筒が最初から下限まで落ちる | 鏡筒の重さを連動拘束だけで支えていた | 支柱・鏡筒に `gravcomp="1"`（実機の高さ調整ネジが自重を支えるのに相当） |
| 傾き:移動 の比が 0.15 にならない | 拘束が柔らかすぎ | `solref="0.004 1"`（時定数を 2×timestep まで小さく） |
| weld を ON にすると発散（NaN） | ジョイスティック（約30g）が本体・アームに比べて軽すぎ、2ms刻みでは計算が追いつかない | 関節の見かけの慣性 `armature` を 0.005→0.05、weld は `solref="0.01 1"` |

パラメータを12通り試して決めた（timestep 1ms にすれば軽いままでも安定するが、計算が2倍遅くなるので不採用）。

## 7. 結果（scripts/m1_demo.py）
- 連動の比：左右 0.1500 m/rad、高さ 0.00318 m/rad（設計値と一致）。
- 指令への追従誤差：平均 **0.82 mm**、最大 **2.64 mm**（動いている最中の遅れ。止まると 0.0 mm）。
- 手とノブのずれ：最大 0.10 mm。
- グラフ：`outputs/m1_demo_plot.png`（灰色の破線＝目標、オレンジ＝実際）。

## 8. 試してみよう
1. `scene.xml` の `link_x` の係数 0.15 を 0.10 に変え、`slitlamp_api.py` の `K_XY` も同じ値にして `m1_demo.py` を実行する。同じ移動量でも、ジョイスティックを大きく倒すようになる。
2. `sim/arm_ik.py` の `damping`（λ）を 0.02 → 0.0001 にしてみる。特異姿勢の近くでアームがどう振る舞うかを見る。
