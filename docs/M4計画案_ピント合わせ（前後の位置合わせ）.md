## 0. ひとことで言うと
細隙灯では、左右・上下だけでなく、**前後（ピント）**も合わせる必要がある。シミュレータに「ピントのずれによるボケ」と「前後の操作」を加え、生徒AIが画像だけでピントまで合わせられるかを確かめる。

## 1. 今の状態
| 項目 | 今 |
|---|---|
| カメラ | MuJoCo のカメラはピンホール（針穴写真機）なので、**どの距離もくっきり写る**（ボケがない） |
| 前後の操作 | ジョイスティックの前後の傾き（`js_pitch` → `lamp_y`）は設計図にあるが、制御では **0°に固定** |
| 患者の前後位置 | 頭の位置は左右・上下だけランダムで、前後は固定（カメラから瞳孔まで常に約19.7cm） |
| 合格の基準 | 左右・上下のずれだけ（1mm未満） |

→ 今は「ピントは常に合っている」という前提になっている。

## 2. 問い
1. 生徒AIは、細隙灯カメラの画像だけで、左右・上下に加えて**前後（ピント）も**合わせられるか。
2. ボケだけでは「近すぎ」か「遠すぎ」か分からない。生徒はどの手がかりで前後の向きを判断するか（スリット光の位置、時間変化）。

## 3. 何を作るか
### 3.1 ボケを作る（見た目）
- MuJoCo の描画では、色の画像と一緒に**各画素までの距離（深度画像）**も取れる（`Renderer.enable_depth_rendering()`）。
- 焦点距離から外れた距離ほど強くぼかす後処理を入れる。ボケの大きさは、レンズの**錯乱円**の式でずれの量から決める。
- 実装の考え方：距離をいくつかの層に分け、層ごとに強さの違うぼかし（ガウシアン）をかけて合成する。
- 角膜・虹彩・瞼の縁で奥行きが違うので、ピントを合わせる面によって、くっきり写る部分が変わる。
- 焦点距離・絞り（ボケの強さ）・被写界深度は、パラメータとして調整できるようにする。

### 3.2 前後の操作を加える
- 指令を (Δx, Δz) から **(Δx, Δy, Δz)** の3つに増やす。Δy はジョイスティックの前後の傾き（`js_pitch`）で、本体を前後に動かす（連動の係数 −0.15 m/rad は設計図に既にある）。
- `sim/slitlamp_api.py`：`lamp_to_joystick`・`knob_pose`・`command` に前後の傾き（pitch）を加える。IK はそのまま使える（ノブの目標の位置・向きが変わるだけ）。
- `sim/env.py`：
  - 患者の前後の座り方をランダムにする（例：±5mm）。
  - 開始時の前後のずれもランダムにする。
  - `error()` に前後のずれ（y）を加える。
- 先生（`expert/expert_policy.py`）：瞳孔（または合わせる面）の本当の奥行きを知っているので、これまでと同じ比例制御で前後も合わせられる。
- 合格の基準：左右・上下 1mm未満に加え、**前後のずれが被写界深度の範囲内**（値は倍率・ボケの設定に合わせて決める）。

### 3.3 生徒の脳
- 出力を2つから3つ（Δx, Δy, Δz）に増やす。
- **フレームスタック（直前の画像も一緒に見せる）**ありとなしの2通りを作り、比べる。

## 4. 難しいところ：ボケだけでは前後の向きが分からない
- ボケの量は、ピントが前にずれても後ろにずれても、ほぼ同じに見える。**1枚の画像だけでは、どちらへ動かせばよいかが決まらない。**
- **手がかり①：スリット光の位置**
  - 実際の細隙灯では、照明系と観察系が同じ焦点に合わせてある。ピントがずれると、スリット光の当たる位置が横にずれ、合うと光が視野の中央に来る。
  - このシミュレータでも、照明は焦点に向けて斜めから当てているので、前後にずれると光の当たる位置が横にずれるはず。生徒がこの手がかりを学べるかが見どころ。
  - 照明の向き（[[M4計画案_照明を眼ごとに耳側へ振る]]）と関係が深い。照明が左右どちらから来るかで、ずれる向きが逆になる。
- **手がかり②：時間変化**
  - 少し動かして、ボケが減ったか増えたかを見る（オートフォーカスの「山登り」と同じ）。
  - 生徒に直前の画像も見せる（フレームスタック）必要がある。
  - 「動いて確かめる」能動的な知覚（active perception）で、Physical AI らしい論点。
- **手がかり③：像の大きさ**
  - 近いほど大きく写る。ただし、実際の角膜径・虹彩径には個人差があるので、決め手にはなりにくい。

## 7. 注意点
- **ボケは後処理で作る近似。** 本物のレンズの光学（収差、照明のボケ方）とは違う。レポートに明記する。
- 照明（スポットライト）は MuJoCo の描画の中で当たるので、光の当たる位置のずれは物理的に再現される。ボケだけが後処理になる。
- 指令が3つになると、M2・M3のお手本・生徒はそのまま使えない（作り直し）。既存の2つの指令の環境は、既定の設定として残す（M3の結果はそのまま有効）。
- アームは前後の傾きでも手首の向きを合わせる必要がある。IK・手首の可動範囲で問題が出ないか、Step 2 で確認する。

## 8. レポートでの位置づけ
- **臨床の論点：** 細隙灯のピント合わせは、照明と観察が同じ焦点を共有する構造（スリット光が中央に来る＝ピントが合う）を利用している。眼科医の暗黙知を、シミュレータと学習の設計に落とし込む。
- **AIの論点：** 1枚の画像では決まらない量（前後の向き）を、手がかりの設計（照明）と時間の情報（フレームスタック）でどう補うか。能動的な知覚の例。
- **照明の案との組み合わせ：** 照明を耳側へ振ると、スリット光のずれる向きが眼ごとに逆になる。両方を入れると、生徒が「照明の向きとセットで」前後を判断できるかまで確かめられる。

## 9. さらに発展させるなら（今回は行わない）
- 角膜・水晶体前面・水晶体後面など、**どの面に合わせるか**を指示として与え、生徒がその面にピントを送る。実際の細隙灯の使い方に近づく。
- 眼球モデルに水晶体（奥行きのある透明体）を加え、スリット光の光学切片が見えるようにする。

## 10. 更新（2026-10-22）：眼科医からの情報と、計画の具体化
### 10.1 実際の細隙灯での見え方・手順（ユーザー（眼科医）より）
- **見え方：** 手前から奥へ進めていくと、最初はぼやけていて、焦点が合うところでくっきりし、近づきすぎるとまたぼやける。
- **手順：** **手前に引いた状態から奥へ押して、ピントを合わせることが多い。**

### 10.2 計画への反映
- **ボケ方は前後で対称**（手前すぎても奥すぎても同じようにぼやける）なので、1枚の画像だけでは向きが決まらない（§4）。実際の診察では、次の2つでこれを解決していると考えられる。
  1. **手順で向きを決める：** いつも手前から始めて奥へ押す。ぼやけていれば「まだ奥」と分かる。→ **先生のお手本は、必ず手前に引いた状態から始め、奥へ押して合わせる。**
  2. **動かしながら見る：** 押してくっきりしてきたら進め、ぼやけ始めたら行き過ぎなので戻す（山登り）。→ **M4-E で作ったフレームスタック**（直前の画像も見る生徒）で、ボケが減ったか増えたかを見られる。
- **確かめる問い：**
  - 手順どおり（手前から）始めれば、1枚だけ見る生徒でもピントを合わせられるか。
  - 手順に反して「近づきすぎ」から始めると、1枚だけ見る生徒は**さらに奥へ押してしまう**（向きを間違える）か。フレームスタックの生徒は、ぼやけが増えることに気づいて戻れるか。

### 10.3 具体的な設定（案）
| 項目 | 値 |
|---|---|
| ボケの大きさ | 焦点からのずれ1mmあたり、ぼかしの広がり約1画素（96×96の画像で）。±0.5mm以内はほぼくっきり、±3mmで強くぼやける |
| ボケの作り方 | 細隙灯カメラの深度画像から、画素ごとの焦点からのずれを求め、強さの違うぼかしを数段階作って画素ごとに選ぶ |
| 患者の前後の座り方 | ±5mm でランダム |
| 開始位置（手順どおり） | 焦点より **3〜8mm 手前**（検者側） |
| 開始位置（手順に反する試験） | 焦点より 3〜8mm **奥**（近づきすぎ） |
| 指令 | (Δx, **Δy**, Δz)、各最大3mm。Δy はジョイスティックを前後に倒す（連動の係数 −0.15 m/rad は設計図に既にある） |
| 合格の基準 | 左右・上下 1mm 未満、かつ**前後 0.5mm 未満**を0.5秒保つ |
| 生徒 | 1枚だけ見る生徒と、フレームスタック（3枚）の生徒 |
| お手本 | 3,000人 × 2秒（DARTのノイズで、行き過ぎから戻る場面も含める） |
| 比べる方式 | 先生、生徒2種（モジュール型は前後を判断できないので、左右・上下だけの参考） |

- 前後を使わない既定の設定では、ボケも前後の操作もなし（M2〜M4の結果はそのまま有効）。
- 目安の日程：実装 1日、計算 約2時間、記録・動画で、合計約2日（10/22〜24）。そのあと M5。
