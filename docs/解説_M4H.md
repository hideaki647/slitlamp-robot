# 解説 M4-H：ピント合わせ（前後の位置合わせ）

実施：2026-10-22〜25　／　計画：[[M4計画案_ピント合わせ（前後の位置合わせ）]]　／　関連：[[解説_M4E]]・[[ジョイスティック操作の仕組み]]・[[M4計画案_一覧]]

## 0. ひとことで言うと
細隙灯カメラの画像に、**焦点からのずれに応じたボケ**を加え、ロボットが**前後（奥行き）にも動ける**ようにした。臨床の手順どおり**手前に引いた状態から始めると、画像だけを見る生徒は78〜86%でピントを合わせられた**（先生は100%）。失敗はすべて「焦点の0.5〜1.2mm手前で止まる」もの。一方、**近づきすぎた位置から始めると、生徒はさらに奥へ押してしまった**（成功0〜16%）。ボケは前後で対称なので、1枚の画像からは「手前すぎ」と「奥すぎ」を区別できないことが、実験ではっきり示された。

## 1. 作ったもの
### 1.1 ボケ（`sim/env.py` の `_defocus`）
- 細隙灯カメラの**深度画像**（各画素までの距離）を同時に描画し、画素ごとに「焦点からのずれ」を求める。
- ぼかしの強さ σ = **1.0画素／mm × |ずれ|**（96×96の画像）。強さの違うぼかし画像を8段階（σ=0, 0.5, 1, 1.5, 2, 3, 4, 6）作り、画素ごとに近い段階を選ぶ。
- 確認画像：`outputs/m4h_focus_check.png`（ずれ0・±1・±3mm）。ユーザー（眼科医）の確認で「このままでOK」。
- **簡略化（レポートに明記）：** 本物のレンズの光学（収差、照明のボケ方）ではなく、後処理による近似。

### 1.2 前後の操作（`sim/slitlamp_api.py`）
- 指令を **(Δx, Δz, Δy)** の3つにした（各最大3mm／0.1秒）。Δy＝奥へ押す向きが＋。
- 前後は**ジョイスティックを前後に倒す**（pitch）ことで動く（[[ジョイスティック操作の仕組み]]）。可動範囲は±35mm。
- 腕のIK：手首の回転が可動範囲の端でつまずく問題（左眼で1回失敗）があったので、手首の角度を連続になるように解き、範囲を±360°に広げた。

### 1.3 患者と開始位置
- 患者の座る位置を前後に±5mmばらつかせる。
- **手前から（`focus="back"`、臨床の手順・学習に使う）：** 焦点より 3〜8mm 手前（検者側）から始める。
- **近すぎから（`focus="front"`、学習には使わない試験）：** 焦点より 3〜8mm 奥から始める。
- **成功の条件：** 左右・上下 1mm 未満、かつ**前後 0.5mm 未満**を0.5秒保つ。

## 2. お手本（`data/demos_focus`）
- 先生（本当の位置を知っている）は、ずれ×0.5 の指令で3方向を同時に合わせる。DARTのノイズ（0.5mm）を混ぜて、行き過ぎから戻る場面も集める。
- **最初は2秒（3,000人×20ステップ＝6万組）で集めたが、先生は約0.5秒で合わせてしまうので、ほとんどが「ピントが合った後」の場面だった。** ユーザーの判断で **1秒（3,000人×10ステップ＝3万組）に短縮**した（2秒版は `data/demos_focus_2s` に残してある）。

## 5. 分かったこと
### 5.1 手前から：合わせられるが、焦点の少し手前で止まる
- 左右・上下は毎回合った。**失敗（1枚の生徒11人、3枚の生徒7人）はすべて、焦点の0.5〜1.2mm手前で止まったもの。** 大きく外れたものはない。
- 理由（推定）：今の設定では、焦点から1mm以内のボケは σ が1画素以下で、画像の違いがごくわずか。**「ほぼ合っている」と「ぴったり合っている」を画像から見分けられない。** 被写界深度が深すぎる状態に近い。
- 3枚の生徒の方が良かった（86% 対 78%）。押しながら「ボケが減っているか」を見られるためと考えられる。

### 5.2 近すぎから：さらに奥へ押してしまう（安全上の問題）
- 画像だけでは、近すぎも遠すぎも同じ「ぼやけている」に見える。お手本には「ぼやけていたら奥へ押す」場面しかないので、**近すぎるときも奥へ押してしまった**。
- 動かせる範囲の端（26〜34mm奥）まで行った。**実際の患者なら、眼の方へ押し込むことになる。**
- 3枚の生徒は、ぼやけが増えていくことに気づいて引き返せた例がわずかにあった（成功16%、ただし1.6秒と遅い）。
- **臨床との対応：** 眼科医が「手前に引いた状態から奥へ押す」手順を守るのは、まさにこの向きの曖昧さを手順で解消するためだと解釈できる。学習した生徒は、その手順の前提（いつも手前から始まる）ごと覚えてしまっている。

### 5.3 レポートでの論点
- **AIの論点：** 1枚の画像で決まらない量（前後の向き）を、生徒は「お手本の手順」という前提で補っていた。前提が崩れると（分布の外）、自信を持って逆方向へ動く。**時間の情報（フレームスタック）は、この曖昧さを一部だけ解消した。**
- **安全の論点：** 実用には、前後の移動量の上限、「ボケが増え続けたら止まる・戻る」といった安全装置が要る。
