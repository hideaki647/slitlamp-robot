# 解説 M0：Docker環境とシーン（MJCF）

## 0. ひとことで言うと：M0で何をしたのか
**パソコンの中に「診察室」を作った。** 細隙灯・ジョイスティック・顎台・CGの患者を置き、物理法則どおりに動いて、カメラで撮影できる仮想の世界。まだロボットもAIも動かない。舞台づくりの段階。

### やったことは2つ
1. **作業場（Docker）を用意した**
   - 物理シミュレータ MuJoCo は、Windowsのセキュリティ機能（Smart App Control）にブロックされて直接は動かなかった。
   - そこで、Windowsの中に小さなLinuxの箱（Dockerコンテナ）を作り、その中で動かすことにした。セキュリティ設定は変えていない。
   - 箱の中身（Python・MuJoCo・PyTorch など）は設計図（`Dockerfile`）に書いてある。だれのパソコンでも同じ環境を再現できるので、提出するコードの再現性も保てる。
2. **診察室の設計図（`models/scene.xml`）を書いた**
   - MuJoCo の設計図の書式を MJCF という。「部品（body）」「動き方（joint）」「形（geom）」「カメラ」「照明」を、入れ子の文章で書く。
   - 細隙灯は、基台が左右・前後に、鏡筒が上下に動く。ジョイスティックは前後・左右に傾き、軸が回る。
   - 鏡筒の中に**細隙灯カメラ**（＝検者が接眼レンズで見る視野）を、横に**細隙光**（スポットライト）を付けた。
   - 患者は顎台に頭を乗せたCG。眼球（半径12mm）・虹彩・瞳孔（半径2.5mm）を持ち、瞳孔の中心に目印（site）を置いた。この目印が、のちに先生（M2）が使う「瞳孔の本当の位置」になる。

### 眼科にたとえると
| プロジェクト | たとえ |
|---|---|
| MuJoCo | 診察室の物理（重さ・関節・光）を計算するエンジン |
| scene.xml（MJCF） | 診察室の図面（どこに何を置き、どう動くか） |
| 細隙灯カメラ `slit_cam` | 検者が接眼レンズから見る視野 |
| 瞳孔中心の目印 `pupil_R_center` | シミュレータだけが知る「正解の位置」 |
| Docker | どこへ持って行っても同じに組み立てられる、移動式の診察室 |

### 成果
- 俯瞰の画像と、細隙灯カメラの画像が出るようになった（`outputs/m0_*.png`）。
- 周回する動画で、診察室全体を確認できるようになった。
- 倍率（視野角 fovy 15° と 8°）の見え方を比べ、15° を採用した。

## 1. 環境の3層
```
Windows（コード編集・画像確認）
 └ Docker コンテナ（Linux。Python・MuJoCo・PyTorch 入り）
    └ MuJoCo（仮想世界。models/scene.xml を読み込む）
```
- Windows の `slitlamp_robot/` フォルダは、コンテナ内では `/workspace` として見える（ボリュームマウント）。
- 編集は Windows 側で行い、実行はコンテナで行う。結果（`outputs/`）は Windows 側にそのまま出てくる。

## 2. 設定ファイル
| ファイル | 役割 | 要点 |
|---|---|---|
| `Dockerfile` | コンテナの設計図 | Python 3.12 のLinuxに、描画ライブラリ（EGL/OSMesa）・ffmpeg・CPU版PyTorch を入れる |
| `requirements.txt` | Pythonライブラリ一覧 | mujoco 3.15.0、numpy、opencv、imageio、matplotlib |
| `compose.yaml` | 起動設定 | サービス名 `sim`、フォルダのマウント、`MUJOCO_GL=egl` |
| `.dockerignore` | 設計図に含めないもの | outputs/ や data/ など大きいフォルダ |

**MUJOCO_GL=egl とは**：画面（ディスプレイ）がないコンテナの中で、3D画像を描くための方式。EGL がだめなら `osmesa`（ソフトウェア描画、遅いが確実）に切り替える。

## 3. よく使うコマンド（`slitlamp_robot` フォルダで）
- 環境を作る（初回・Dockerfile を変えたとき）：`docker compose build`
- スクリプトを1回実行：`docker compose run --rm sim python scripts/render_snapshot.py`
- コンテナの中に入って作業：`docker compose run --rm sim bash`（`exit` で出る）

## 4. MJCF（models/scene.xml）の読み方
- `<body>` 部品。**入れ子にすると親に付いて一緒に動く**（基台 → 支柱 → 鏡筒 → カメラ）。
- `<joint>` その body の動き方。`slide`＝直進、`hinge`＝回転。`range` は可動範囲、`damping` は動きの粘り。
- `<geom>` 形と見た目（box/sphere/cylinder/capsule/ellipsoid）。`size` は**半分の長さ・半径**で書く点に注意。
- `<camera>` 仮想カメラ。カメラは自分の **−z方向** を見るので、`xyaxes` で画像の右方向(x)と上方向(y)を指定して向きを決める。
- `<light>` 照明。細隙光はスポットライト（`cutoff`＝光の広がり角）で再現。
- `<site>` 目印の点。物理には影響しない。瞳孔中心（`pupil_R_center`）に置き、あとで先生（エキスパート）が「本当の瞳孔位置」として使う。

## 5. 今のシーンの構造（木構造）
```
world
├ table（診察台、天板上面 z=0.75）
├ lamp_base（基台）      joint: lamp_x（左右）, lamp_y（前後）
│ ├ joystick            joint: js_pitch（前後傾）, js_roll（左右傾）, js_spin（軸回転）
│ └ lamp_column（支柱）  joint: lamp_z（高さ）
│   └ microscope（鏡筒） camera: slit_cam ／ light: slit_light
├ chinrest（顎台）
├ head（頭）
│ ├ eye_R（患者の右眼、x=−0.032）  site: pupil_R_center
│ └ eye_L（患者の左眼、x=+0.032）
└ camera: overview（俯瞰）
```
- 座標：x＝検者から見て右、y＝患者側（奥）、z＝上。単位は m。
- 患者は −y を向いているので、**患者の右眼は x<0 側**（検者から見て左）。眼科で向かい合ったときと同じ。
- 瞳孔間距離 64mm、眼球の半径 12mm、虹彩の半径 6mm、瞳孔の半径 2.5mm。

## 6. M0でのつまずき（記録）
- 最初は瞳孔の周りに白い輪が出た。原因は、虹彩の円盤が眼球の球面より奥にあり、球が虹彩を突き抜けて見えていたこと。虹彩と瞳孔を角膜側に 1mm 前へ出して解決した。
- 細隙光が額に当たっていた → 光源から眼への方向ベクトル `dir` を計算し直した。

## 7. 試してみよう
1. `render_snapshot.py` の `poses` に `"left_eye": 0.032` を追加して、左眼に合わせた画像を出す。
2. `scene.xml` の `slit_cam` の `fovy`（視野角）を 15 → 8 に変えると、細隙灯の倍率を上げたように見える。どのくらいが見やすいか試す。
3. 周回カメラの `elevation` を -20 → -60 にして、真上寄りから見下ろす。

## 8. 試した結果（`scripts/try_m0.py`、元ファイルは変更せず実行時に値だけ書き換え）
- **fovy 15° → 8°**：眼の直径24mmが、画面の高さ 約4割 → 約8割 に拡大した（`m0_try_fovy15_vs_8.png`）。
  - カメラから眼までは約0.21m。見える範囲の縦幅 ＝ 2 × 0.21 × tan(fovy/2) なので、15°で約55mm、8°で約29mm。
  - **トレードオフ**：倍率を上げると瞳孔が大きく写って位置を細かく読めるが、ずれが大きいと眼が画面から外れて、ロボットが手がかりを失う。最初の位置ずれ（±1〜2cm）でも眼が画面に残るように、当面は 15° を採用する。
- **elevation -60°**：机の真上寄りから見下ろす視点になり、細隙灯・顎台・患者の前後の距離関係がわかりやすい（`m0_try_elev60_orbit.mp4`）。一方で、高さ方向の動きは見えにくくなる。提出動画では -20〜-30° 程度が無難。
