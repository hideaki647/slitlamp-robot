# 解説 M2：先生（エキスパート）の自動アライメントと、お手本データの収集

## 0. ひとことで言うと：M2で何をしたのか
**M3で生徒AIが勉強するための「問題集（画像）と模範解答（指令）」を、シミュレータの中で自動で3.6万組作った。**

### お手本は誰の操作か
- **実際の患者や、人間の医師の操作は一切使っていない。** すべてシミュレータの中のCGと、プログラムの「先生」によるもの。
- 先生は画像を見ない。シミュレータだけが知っている「瞳孔中心の本当の座標」を使い、「ずれ × 0.5」だけ動かすという単純な規則で操作する。答えを知っているので、模範解答はいつも正確。
- 生徒（M3）はこの答えを知らされず、**画像だけから**同じ指令を出せるように学ぶ。シミュレーションでのロボット学習でよく使われる「特権情報を持つ先生 → 画像だけの生徒」という型。

### 3.6万組の作り方（`learning/collect_demos.py`）
1. **CGの患者を3,000人分作る。** 毎回、頭の位置・瞳孔の大きさ・虹彩の色・肌の色・照明をランダムに変える。
2. **細隙灯を瞳孔から少しずらした位置から始める**（左右±15mm、上下±8mm）。
3. **0.1秒ごとに2つを記録する。**
   - 細隙灯カメラの画像（96×96）→ 生徒への**問題**
   - 先生がそのとき出した指令（Δx, Δz mm）→ **模範解答**
4. 1人あたり12回（1.2秒）記録するので、**3,000人 × 12回 = 36,000組**。16並列で約5分。
5. 保存先は `data/demos/ep_00000.npz 〜 ep_02999.npz`（1人＝1ファイル）。

### 研修医にたとえると
| プロジェクト | たとえ |
|---|---|
| 先生（エキスパート） | 答え（瞳孔の本当の位置）を知っている指導医 |
| お手本データ3.6万組 | 「この見え方のとき、指導医はこう動かした」という症例写真集 |
| 生徒AI（M3） | 写真集だけで勉強し、見え方から操作を判断できるようになる研修医 |
| ドメインランダム化 | いろいろな患者（瞳孔径・虹彩色・座り方・照明）を経験させる |
| DARTのノイズ | 指導医がわざと少しずらして、「ずれたところから戻す」場面も見せる |

### M3でどう使うか
- 3.6万組を**勉強用 3.24万組**と**確認テスト用 3,600組**に分ける（患者単位で分けるので、似た問題がテストに混ざらない）。
- 勉強用を40周くり返し学び、確認テストで「生徒の指令が先生と何mmずれたか」を測る（筆記試験）。
- そのあと、未知の患者50人で生徒に一人で操作させる（実技試験）。

### シミュレータを使う利点と限界
- **利点：** 人が操作しなくても、何万組でも自動で、正確な正解付きで作れる。
- **限界：** 実機に応用するには、シミュレータと実際の見え方の違い（Sim-to-Real）が課題になる。レポートの考察で扱う。

## 1. 全体の流れ
```
┌─ 1エピソード（1回の診察）───────────────────────────────────┐
│ リセット：患者の位置・瞳孔径・虹彩の色・肌の色・照明をランダムに変え、    │
│           細隙灯を瞳孔から少しずれた位置で「握った状態」から開始        │
│ 0.1秒ごと：                                                    │
│   細隙灯カメラで撮影（96×96）──────────┐ 記録（生徒の入力）       │
│   先生：ずれ = 瞳孔中心の真の位置 − 光軸    │                      │
│         指令 = 0.5 × ずれ（最大3mm）───┘ 記録（生徒の正解ラベル）  │
│   実際に動かすのは 指令＋小さなノイズ（DART）                         │
│   アーム → ジョイスティック → 本体（M1の仕組み）                       │
└─────────────────────────────────────────────┘
```

## 2. 用語
| 用語 | 意味 |
|---|---|
| **エピソード** | リセットから終了までの1回の試行（＝1回の診察）。 |
| **ステップ** | 「見る → 決める → 動かす」の1サイクル。本プロジェクトでは0.1秒（10Hz）。 |
| **観測（observation）** | ポリシーに与える情報。生徒には細隙灯カメラの画像だけを与える。 |
| **行動（action）** | ポリシーの出力。「本体をあと Δx, Δz [mm] 動かせ」という差分。 |
| **特権情報（privileged information）** | シミュレータだから知っているが、実機では得られない情報。ここでは瞳孔中心の真の3次元位置。 |
| **エキスパート（先生）** | 特権情報を使って必ず上手く操作するポリシー。お手本データを作る役。 |
| **P制御（比例制御）** | 指令 = ゲイン × ずれ。ずれが大きいほど大きく動かす。 |
| **DART** | お手本を集めるとき、実行する指令にだけノイズを混ぜる手法（Laskey et al., 2017）。記録するのはノイズなしの正解。 |
| **ドメインランダム化** | 患者・照明などの条件をばらつかせて、学習したAIが条件の違いに強くなるようにすること。 |

## 3. 先生（expert/expert_policy.py）
- ずれ e = （瞳孔中心の位置）−（細隙灯カメラ＝光軸の位置）の左右 x と高さ z。
- 指令 a = 0.5 × e、1ステップで最大3mm。
- ゲイン0.5なら、ずれは毎ステップ半分になる：10mm → 5 → 2.5 → 1.25 → 0.6mm。
- **画像を一切見ない**ので実機では使えない。生徒（M3）は、この指令を**画像だけから**再現できるように学ぶ。

### なぜ指令を「差分」にするか
画像から読み取れるのは「瞳孔が画面の中央からどれだけずれているか」で、細隙灯の絶対位置は読み取れない。差分の指令なら、画像だけで決められる。

## 4. 環境（sim/env.py）のランダム化
| 項目 | 範囲 |
|---|---|
| 頭の位置（顎台での座り方） | 左右 ±10mm、上下 ±8mm |
| 開始位置（瞳孔からのずれ） | 左右 ±15mm、上下 ±8mm |
| 瞳孔の半径 | 1.5〜4.0mm |
| 虹彩の色 | 濃い茶・茶・ヘーゼル・緑・青 × 明るさ±15% |
| 肌の色 | 基準色 ±0.06 |
| 細隙光・室内光の明るさ | ×0.7〜1.3 |

- 開始位置を大きくずらしたため、左右の可動範囲を広げた（ジョイスティック ±20° → ±25°、本体 ±60 → ±70mm）。

## 5. M2でのつまずき（記録）
### 5.1 本体の動きが指令より遅れ、合った後に行き過ぎる
- 症状：指令から0.1秒たっても本体がほとんど動かず（13.06 → 13.09mm）、その後に行き過ぎて戻る（0.85 → 1.86mm）。
- 原因：アームの位置制御モーターの「ブレーキ（kv=15）」が「ばね（kp=150）」に比べて強すぎた。反応の時定数の目安は kv/kp ＝ 0.1秒で、制御周期（0.1秒）と同じ長さの遅れになっていた。
- 試したこと：

| kp / kv | 3mm指令の0.1秒後 | 0.2秒後 |
|---|---|---|
| 150 / 15（M1） | 1.07mm（36%） | 2.26mm |
| 150 / 6 | 1.76mm | 2.93mm |
| **250 / 6（採用）** | **2.27mm（76%）** | **3.05mm** |
| 250 / 3 | 2.64mm | 3.03mm |
| 400 以上 | 発散 | — |

- 結果：先生の行き過ぎが消えた。M1のデモの追従誤差も **平均0.82 → 0.19mm、最大2.64 → 0.47mm** に改善した。

### 5.2 1回目のデータが「ほぼ合った状態」に偏った
- 1回目の設定（ノイズ1.0mm、最大50ステップ、1,000エピソード）：ノイズが合格基準（1mm）と同じ大きさで、合った位置の周りでふらつき続けた。4mm以上ずれた場面は全体の9%だけだった。
- 2回目の設定（ノイズ0.5mm、**12ステップ＝1.2秒で打ち切り**、3,000エピソード）：「近づく場面」と「微調整の場面」がおよそ半々になった。

| ずれ | 1回目（4.97万組） | 2回目（3.6万組） |
|---|---|---|
| 0〜1mm | 19.7% | 38.7% |
| 1〜2mm | 36.3% | 29.0% |
| 2〜4mm | 34.7% | 12.4% |
| 4〜8mm | 6.8% | 10.6% |
| 8mm以上 | 2.5% | 9.3% |

### 5.3 Docker が起動しない（10/14）
- 10/13 夜に Docker が `wsl --version` の実行に一時的に失敗し、エンジンが停止したままになっていた。WSL 自体は正常だったので、`docker desktop restart` で復旧した。

## 6. 結果
### 先生の評価（scripts/eval_policy.py、学習データと重ならない患者条件 seed 10000〜 × 50回）
| 指標 | 値 |
|---|---|
| 成功率（ずれ1mm未満が5ステップ続く） | **100%** |
| 収束時間 | 平均 **0.43秒**、最大0.6秒 |
| 最終誤差 | 平均 **0.02mm** |
| 開始時のずれ | 平均 9.6mm |

### お手本データ（learning/collect_demos.py）
| 項目 | 値 |
|---|---|
| エピソード数 | 3,000（seed 0〜2999） |
| 画像と指令のペア | **36,000組**（1エピソード12組） |
| 1.2秒以内に1mm以内へ到達 | 98.2% |
| 容量 | 345MB（`data/demos/`、GitHubには上げない） |
| 収集時間 | 約4.7分（16並列） |

- データ形式（1エピソード＝1ファイル `ep_XXXXX.npz`）：`images (12,96,96,3) uint8`、`actions (12,2) [mm]`、`errors (12,2) [mm]`（errors は分析専用で、生徒には見せない）。
- サンプル一覧：`outputs/m2_demo_samples.png`（赤い矢印＝先生の指令の向きと大きさ、緑の十字＝画面の中央）。

### 動画
