# 解説 M4-G：遅延・ノイズへの強さ（実用化を見すえた試験）

実施：2026-10-17　／　計画：[[M4計画案_G_遅延・ノイズへの強さ]]　／　関連：[[解説_M4A]]・[[M4計画案_一覧]]

## 0. ひとことで言うと
実機で避けられない「遅れ」「ばらつき」「ノイズ」をシミュレータに入れ、先生・モジュール型・生徒2種を**学習し直さずに**試した。**いちばん効いたのは観測の遅れで、0.2秒で全方式がほぼ失敗した。** これは画像の読み方ではなく、比例制御そのものの性質で、**制御理論の計算どおり**だった。理論から求めた「遅れに合わせてゲインを下げる」と、0.3秒の遅れでも100%に戻った。モーターの個体差（×0.5〜1.5）と画像の質には、全方式ともほぼ影響されなかった（閉ループ制御の強み）。

## 1. 入れた不完全さ（`sim/env.py` の `disturb`、既定はすべて「なし」）
| 種類 | 入れ方 | 試した強さ | 実機での原因 |
|---|---|---|---|
| 観測の遅れ | 方式が受け取る画像（先生はずれ）を、kステップ前のものにする | 0.1・0.2・0.3秒 | カメラの読み出し、画像処理・推論の時間 |
| 指令のばらつき | 実行する指令に毎回ランダムなずれを足す | 標準偏差 0.1・0.3・0.5mm | ギアのがた、摩擦 |
| モーターの個体差 | アームのモーターの強さ kp を倍率で変える | ×0.5・0.7・1.3・1.5 | 個体差、経年変化 |
| 画像の質 | 画素のノイズ、ぼけ | ノイズ2%・5%、ぼけ0.5・1画素 | センサーのノイズ、ピントの甘さ |

- 乱れの乱数は、患者の乱数と分けた（同じ50人で、乱れだけが違う）。
- 遅れのとき、先生にも遅れたずれを渡す（先生だけ最新の情報を使うと、比べる基準として不公平）。
- 新しい指標（`learning/rollout.py`）：**振動の回数**（左右のずれの向きが入れ替わった回数）、**合った後の最大のずれ**。

## 3. 制御理論との照合（遅れ）
先生も生徒も「ずれ × 0.5 だけ動かす」比例制御。遅れがkステップあると、ずれは次の式で変わる。

　**次のずれ ＝ 今のずれ − ゲイン × （kステップ前のずれ）**

この式の特性方程式 z^(k+1) − z^k + ゲイン = 0 の根の大きさの最大値が、「ずれが1ステップで何倍になるか」の目安。1を超えると発散する。

| 遅れ | ゲイン0.5での倍率（理論） | 安定なゲインの上限 | 最も速く収まるゲイン |
|---|---|---|---|
| 0秒 | 0.50 | 1.50 | 1.00 |
| 0.1秒 | 0.71 | 1.00 | 0.25 |
| 0.2秒 | **0.94**（ぎりぎり） | 0.62 | 0.15 |
| 0.3秒 | **1.02（発散）** | 0.45 | 0.11 |

- **0.3秒：理論どおり発散した**（全方式0%）。
- **0.2秒：理論では「ゆっくり収まる」はずだが、実際はほぼ失敗した（8〜10%）。** アーム自体にも約0.1秒の反応の遅れ（モーターが目標に追いつくまでの時間、M2で調整）があり、実質の遅れが0.3秒相当になったためと考えられる。
- **理論から求めたゲインに下げると、先生は100%に戻った**（学習し直しなし、制限時間8秒で確認）：

| 遅れ | ゲイン | 成功率 | 収束時間 | 振動の回数 |
|---|---|---|---|---|
| 0.2秒 | 0.5（今） | 12% | 4.1秒 | 13.4 |
| 0.2秒 | **0.15** | **100%** | 0.86秒 | 0.1 |
| 0.3秒 | 0.5（今） | 0% | — | 10.8 |
| 0.3秒 | **0.11** | **100%** | 1.14秒 | 0.0 |

- 代わりに、収束は遅くなる（0.4秒 → 0.9〜1.1秒）。

## 4. 分かったこと
1. **観測の遅れが、いちばん大きな課題。** 方式（画像の読み方）に関係なく、全方式がそろって同じように崩れた。原因は「見てから動くまでの遅れ」と「ゲイン」の組み合わせで、制御理論で予測できる。
2. **実機への要求：** ゲイン0.5のままなら、カメラの読み出し＋画像処理・推論＋通信の合計を**0.1秒以内**に抑える必要がある。それ以上遅れるなら、**遅れに合わせてゲインを下げる**（理論で値を決められる）。
3. **閉ループ制御の強み：** モーターの強さが半分〜1.5倍に変わっても、毎回画像を見て直すので、全方式100%を保った。部品の精度より、「見て直す」仕組みのほうが効く。
4. **指令のばらつき0.5mm**では、合格範囲（1mm）に対してばらつきが大きく、「1mm以内を0.5秒保つ」が難しくなった（68〜80%）。モジュール型がやや弱い（68%）。
5. **画像の質（予想と逆）：** 予想では、しきい値で探すモジュール型がノイズに弱く、データ拡張で慣れている生徒は強いはずだった。実際は、**ノイズ・ぼけでは全方式100%で、精度が落ちたのは生徒のほう（ぼけ1画素で4倍）**。生徒は画素より細かい位置を読んでいるので、ぼけの影響を受けやすい。モジュール型は、もともと0.16mmの誤差があり、ぼけの影響が埋もれた。

## 5. 生徒を遅れに強くする（案3を実施、2026-10-18）
生徒は先生の「ゲイン0.5」の操作を真似しているので、そのままでは遅れに弱い。3つの案を比べ、**案3**を選んだ。
- 案1：遅れを入れた環境で、ゲインを下げた先生のお手本を集め直し、学習し直す（約1時間）。
- 案2：直前の画像も見せる（フレームスタック）生徒にして、生徒自身に調整させる（約1〜2時間）。E の瞬きでフレームスタックを作るので、そこでまとめて試せる。
- **案3（実施）：** 学習はせず、方式の出力に「遅れに合わせた倍率」を掛ける（`eval_policy.py --out_scale`）。倍率は理論の「最も速く収まるゲイン」÷ 0.5：0.2秒 → 0.15/0.5 = **0.3**、0.3秒 → 0.11/0.5 = **0.22**。

### 結果（未知の患者50人）
| 方式 | 遅れ0.2秒（倍率なし → 倍率0.3） | 遅れ0.3秒（倍率なし → 倍率0.22） |
|---|---|---|
| 先生 | 8% → **100%**（1.09秒、0.19mm） | 0% → **100%**（1.47秒、0.26mm） |
| モジュール型 | 8% → **100%**（1.09秒、0.21mm） | 0% → **100%**（1.45秒、0.25mm） |
| BC | 10% → **100%**（1.10秒、0.21mm） | 0% → **100%**（1.47秒、0.28mm） |
| BC+DAgger | 8% → **100%**（1.09秒、0.19mm） | 0% → **100%**（1.47秒、0.27mm） |

（括弧内は収束時間、最終誤差。振動の回数はどれも0.1回以下）

- **学習し直さずに、全方式が100%に戻った。** 「理論 → 先生 → 生徒・モジュール型」のすべてで、「遅れに合わせてゲインを下げれば直る」ことがそろった。
- 代わりに、収束は 0.4秒 → 1.1〜1.5秒 に延びる。最終誤差も 0.2〜0.3mm に増える（ゲインが小さく、5ステップ保った時点でまだ近づいている途中のため）。
- 実機では、カメラ〜推論の遅れを測っておけば、倍率は理論で決められる。遅れが変わる場合（通信など）は、遅れを測りながら倍率を変える、または案2のように生徒に動きの変化を見せる必要がある。
